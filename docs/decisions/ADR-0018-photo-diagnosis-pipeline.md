# ADR-0018: Photo diagnosis is a staged pipeline that is allowed to say no: a quality gate, a measured classifier, an independent vision model, and the same safety stack as /ask

- **Status:** Accepted
- **Date:** 2026-10-10
- **Deciders:** Shabbir (approved the downloads and the Groq quota for the measurement on 2026-10-10; delegated every design choice below) + Claude as implementer
- **Implements:** `docs/ai/multimodal-vision.md`. Amends ADR-0004 (the vision model's name). Reuses ADR-0008 (storage), ADR-0013 (code authors the answer), ADR-0014 (crop scope), ADR-0016 (doses only as label cards) and ADR-0017 (caps, web app).

## Context
Phase 7 of the roadmap is "image diagnosis with OOD + abstention", verified by **cross-domain accuracy measured and recorded in the repo**. The design documents had already fixed the shape (a classifier that sees, a vision-language model that explains, retrieval that grounds, deterministic code that decides whether any dose may be stated) and the one rule that matters most for photos: a classifier trained on lab images (PlantVillage) can score ~99 % there and collapse on field photos **while staying confident**, so the system must be able to refuse.

Three facts found while building this changed details of the plan:
- **`qwen/qwen3.6-27b` (ADR-0004) is gone.** `models.list` on 2026-10-10 returns `qwen/qwen3.8-27b` and no other vision model; Groq's vision page names the same one: text and images in, JSON object mode, at most 3 images and 20 MB per request, each image counted as 2,048 input tokens, status Preview. (It also says JSON Schema mode works, contrary to the earlier note that the vision model has no structured output; this ADR uses JSON object mode and validates the result itself.)
- **Most Indian crops have no open, documented field-photo classifier.** The only open model found that covers wheat and rice (`HurudzaAI/plantdiseasedetection1`, ViT-tiny, MIT or Apache-2.0, the card says both) was trained on "public datasets and our own private data" with no list, and I found no open **field** wheat set with documented classes to validate it against (the one open field wheat set is object detection with unnamed category ids). A model that cannot be measured is not used (CLAUDE.md rule 4).
- **A closed-set classifier always names a class.** The model chosen has 38 classes; a photo of a boot gets one of them. Everything in the OOD design follows from that.

## Decisions

1. **The pipeline is staged, and the cheap, local, deterministic stages run first.** Sanitise the upload; quality gate; ONNX classifier with an out-of-distribution check; **only then** the vision-language model; then an agreement rule; then retrieval, a label-card lookup and the answer model; then `finalize_advisory`, the same stack as `/ask`. A photo that is refused at any local stage never reaches the vision provider (cheaper, and the farmer's photo goes nowhere it need not). `app/vision/diagnose.py`.

2. **Classifier: the backbone of `rodynaemad/plant-disease-dinov2-small`, with a head trained here on field photos (decided after the measurement, see "What was measured").** The model as published is a DINOv2-small backbone, frozen, with a linear head over the 38 PlantVillage classes (int8 ONNX, 24 MB, CC-BY-SA-4.0; its `features` output makes a feature-space OOD score possible). Candidate order was fixed before measuring (`evals/vision/README.md`): this one first; `onnx-community/mobilenet_v2_1.0_224-plant-disease-identification-ONNX` (2.7 MB int8; licence "other") only if this one qualified no crop. Rejected without measuring: the wheat/rice ViT-tiny (above); a full fine-tune of the backbone (no GPU here; the roadmap lists a fine-tuned field classifier as post-hackathon). A linear head on frozen features, which needs no GPU, was added after the measurement (below). The file is **pinned** (Hugging Face commit and SHA-256 in `data/vision/model-manifest.json`, committed), fetched at image build by `app/vision/fetch_model.py`, which fails the build on any other hash, and the classifier refuses to load a file whose hash is not the one the calibration was measured for.

3. **The model's own accuracy number is not used.** The card says 98.9 % on unseen PlantVillage leaves. That is a lab number, was not reproduced here and is not quoted as a result. The headline is the accuracy on **field photos** (PlantDoc), measured by this project (CLAUDE.md rule 4).

4. **Calibration is data, and the system is fail-closed on it** (`data/vision/calibration-v1.json`, `app/vision/calibration.py`). It holds the fitted temperature, the chosen OOD score and its threshold, confidence bands with the accuracy each band actually had, and a per-crop decision. It ships as `status: "uncalibrated"`, and an uncalibrated or missing or mismatched file means **no photo is ever diagnosed** (`vision_not_calibrated`). It is written by `evals/vision/vcalibrate.py` from a calibration split disjoint from the test split the report quotes, under a protocol written before any photo was classified.

5. **OOD: four candidate scores, one chosen by measurement.** Max softmax at the fitted temperature, max logit, energy, and cosine similarity of the feature vector to per-class centroids. The one with the highest mean AUROC on the calibration data (field photos against rice, bean and object photos) is used; the threshold is the one with the largest coverage that still gives >= 0.80 accuracy on accepted calibration photos and <= 0.10 false accepts on the pooled OOD calibration photos. A photo also needs a calibrated top-1 probability of at least 0.5.

6. **A crop is diagnosed only if a measurement qualified it** (rule P7): AgriAI has the crop, at least 25 calibration photos of it were accepted, and their accuracy is >= 0.80. Otherwise `crop_not_validated`. Crops the model has but AgriAI does not (apple, grape, peach, ...) are `crop_not_supported`. Wheat, rice and every crop with no class are out of distribution by construction.

7. **The vision model is an independent second opinion, not an explainer of the classifier's answer.** It sees the photo and a **closed vocabulary** (the label map's crop and condition keys, plus wheat, rice, `other_*`, `unclear`) and nothing about the classifier or the farm, so agreement means something. A diagnosis needs it to name **the same crop and the same condition as the classifier's top choice**; naming the second choice is a disagreement, not a partial win (`model_disagreement`, with a stable sub-reason). Output is JSON object mode, parsed into the vocabulary (an unknown word becomes `unclear`), retried once, and an unusable or unreachable vision model is an honest refusal (`vision_unavailable`), never a diagnosis from the classifier alone. Farm context goes to the answer step, after the decision.

8. **The vision model's text and the photo itself are untrusted.** One free-text sentence (<= 240 characters, control characters stripped) is shown as "what the AI saw" only after the dose guard and the banned-molecule guard, and reaches the answer model only inside a `<photo_observation>` block that says it is data. The pipeline eval includes photos with a printed instruction.

9. **The answer step is the `/ask` stack, not a new one.** A scan-specific strict schema (`ScanDraft`, an `evidence_basis` with a `photo_check` value) is converted to a `DraftAdvisory` and goes through `finalize_advisory`: every quote verified verbatim, crop scope (ADR-0014) on the diagnosed crop, banned molecules, the dose guard, code-authored abstention text. `/ask`'s own schema is untouched. **A dose appears only as a label card looked up by code** from the verified table by (diagnosed crop, condition); the model is told a card exists and sees no number. Any abstention at the answer step makes the whole outcome an abstention with code's text; the model's own words are never shown on a refusal.

10. **The quality gate is measurement, not taste** (`app/vision/quality.py`): shorter side, sharpness (variance of the Laplacian at a fixed 512 px scale), brightness, near-black and near-white shares, and a deliberately low "is there a leaf-coloured pixel at all" bar. Thresholds are data (`data/vision/quality-thresholds-v1.json`), derived from percentiles of real field photos so a stated small share of real photos is rejected, then measured on a different set and on synthetic degradations. A rejected photo is a normal 200 with a retake tip, is neither stored nor counted against the farmer's daily checks.

11. **Uploads are sanitised before anything sees them** (`app/vision/imaging.py`): size cap, file type from the magic bytes, pixel count from the header before decoding (a bomb is refused), a real decode, EXIF orientation applied then **all metadata dropped by re-encoding** (a phone photo carries GPS and a device id), downscale to 1024 px. The classifier, the vision provider and the stored copy see only the re-encoded JPEG.

12. **Photos are stored in a private bucket under the farmer's own session** (ADR-0008): `crop-photos`, JPEG only, 2 MiB, policy on `storage.objects` = the first path segment is a farm the caller owns; the API uploads with the caller's JWT so there is no server key that can bypass it. Storage is best effort for saving a scan (a failure keeps the diagnosis, `image_path: null`) and required for deletion. The app shows a one-hour signed URL.

13. **Caps share the model budget.** A photo check costs a vision call plus an answer call, so `POST /farms/{id}/scans` is capped (5 per user, 12 global a day) **and** counts toward the 35-a-day global figure `/ask` is capped against, because both draw on the same gpt-oss-120b free-tier budget (`asks_in_last_day()` now counts both). A photo the quality gate refused costs nothing and is not counted.

14. **The farm record is evidence too (added after the live measurement).** If the farm's recorded crop is known and the two models agree the photo is a different crop, the photo is refused with `crop_differs_from_farm`, before retrieval and the answer call (`decision.decide_against_farm`). An earlier version only put a note beside the diagnosis; the rice-called-maize case showed a note is not enough.

15. **The farmer never sees a raw score as "confidence".** The agreed estimate is shown first with the other two candidates as "it could also be", a band (high / medium / low), and the accuracy that band actually had on field photos with the number of photos and what they were. `candidates[].probability` exists for the API and the evals only. Disease names have English and Hindi; **the Hindi names have had no native-speaker review** (`name_hi_status: "unreviewed"`, CLAUDE.md section 6).


## What was measured (2026-10-10; full tables in `evals/results/vision-2026-10-10.md`, protocol in `evals/vision/README.md`)
The protocol was written first and its two dated addenda (A1, A2) were each written before the photos they concern were scored.

- **Candidate 1, the model's published head, failed.** On PlantDoc field photos its top-1 accuracy was **36.8 % on the calibration photos and 41.8 % (95 % interval 35.1 to 48.9) on the 225 test photos**, against the 98.9 % on lab photos on its card. Its out-of-distribution scores barely beat a coin (mean AUROC 0.58 to 0.59), its temperature was 3.55 (strongly over-confident), the protocol's accuracy-and-false-accept target could not be met at any threshold, and **no crop qualified**. This is the lab-to-field collapse the design was written to survive; it is stated, not hidden.
- **Candidate 3, the same backbone with a linear head trained on PlantDoc-train photos (A2), is what ships.** Cross-domain top-1 accuracy on the PlantDoc test photos: **64.4 % (95 % interval 58.2 to 70.7)**, top-3 **87.6 % (83.1 to 92.0)**, macro-by-class 63.6 %. 5 test photos are near-duplicates of training photos (cosine >= 0.98); without them top-1 is 65.0 %. Over-confidence is gone (temperature 0.90). These are accuracies on **web-scraped PlantDoc-style photos**, not on Indian smallholder phone photos, and per-class test sets have 6 to 12 photos.
- **Selective prediction works as designed:** at the chosen threshold the classifier stage accepts 36 % of the test photos and is right on **86.6 %** of those; the confidence bands held on the unseen test photos (high 97.7 % of 44, medium 79.2 % of 24, low 64.3 % of 14, against 93.9 / 79.5 / 58.9 % on calibration).
- **Out-of-distribution handling is the weak part.** The chosen score (energy) separates object photos well (AUROC 0.86) and bean leaves less well (0.78), but **rice leaves hardly at all (0.55): 21.4 % of rice photos are accepted by the classifier stage** (the feature-space score does better on rice, 0.68, but worse overall on the calibration data, so the protocol did not choose it). Rice is exactly the kind of Indian crop the classifier has no class for. The independent second model is the safety net for this case and is measured in `evals/results/vision-pipeline-2026-10-10.md`; the classifier alone is **not** enough.
- **Only one crop qualified under the pre-registered rule: maize.** Calibration: 85 accepted photos at accuracy 0.80 (exactly the bar); on the test photos 19 of 23 maize photos were accepted at 78.9 % accuracy. That is borderline and is reported as such. **Tomato did not qualify** (accepted calibration photos right 61 % of the time; test top-1 over all 66 tomato photos 43.9 %), nor potato (7 accepted calibration photos) or soybean (5). So the demo farm's tomato (and wheat) photo gets an honest `crop_not_validated` / out-of-distribution refusal today, and the verified tomato blight label rows cannot be reached by a photo yet. A tomato-specific field dataset is the missing ingredient, not code.
- **The second model, live (`evals/results/vision-pipeline-2026-10-10.md`; 36 PlantDoc test photos, 8 rice photos; read counts, not percentages).** It named the crop right on 30 of 36 photos but the exact condition on only 17 of 36 (47 %), so it is a check, not a diagnostician. Where it and the classifier agreed on crop and condition (14 of 36) the pair was right 12 times (86 %). Through the whole pipeline: 18 photos refused as out of distribution, 7 rejected by the quality gate, 6 `model_disagreement`, and 5 diagnoses, of which 4 were PlantDoc photos (0 wrong) and **1 was a rice photo**: the classifier called all 8 rice photos a maize class, the second model said "rice" for 4 of 8, and for one it agreed with the classifier. A wrong diagnosis on an unsupported crop is the failure the two-model rule is meant to stop, and it got through once in 8. **Consequence, added after this finding and not re-measured live:** `decide_against_farm` refuses (`crop_differs_from_farm`) a photo that the two models agree is another crop than the farm record's (a rice farm never receives a maize diagnosis); a farm with no recorded crop has no such protection. Tokens: about 2,000 prompt tokens per photo for the vision model (95K for 45 calls), 7.5K for 5 answer calls. A printed-instruction test reached the answer step with only one photo (no leak; thin evidence, see the report); Groq rate-limited the vision model during the follow-up.
- **Quality gate:** thresholds from PlantDoc-train percentiles reject 10.3 % of real train photos and **15.6 % of real test photos** (mostly the fixed 224 px size floor: many web photos are small), above the 5 % the protocol aimed for; this is reported, and the size floor was not relaxed after seeing the test photos. It stops 100 % of blurred (radius 3 and 6), darkened and shrunk copies and 95 % of washed-out ones, and 47 % of object photos.
- **Latency:** 31 ms per photo for the classifier on the development laptop (not measured on the deployed host).

## Options considered
- **One call to a vision model that diagnoses.** Simplest, and exactly the failure the design is built against: a general VLM explains a named disease better than it sees one, and nothing in a single call can say "no". Kept only as the second opinion.
- **Classifier alone.** Cheaper, no second provider, but a closed-set model is confidently wrong on field photos and on anything outside its classes. The second, independent check is what turns "the classifier said so" into "two different models named the same thing".
- **A learned OOD detector or a larger model.** More to build, to host (a 4 GB image does not fit the free tier) and to measure than the scores above; revisit with field data.
- **Similarity-based abstention (as in ADR-0013).** Same lesson: choose a score by measurement, do not assume one.
- **Fine-tuning on PlantDoc.** Was deferred to post-hackathon in the first version of this ADR, and was then done in its smallest form (a linear head on frozen features, ~200 KB) because the published head qualified nothing (protocol addendum A2). The PlantDoc test photos stayed untouched, and calibration photos are disjoint from head-training photos. A full fine-tune of the backbone is still post-hackathon.
- **Show the classifier's softmax as the confidence.** Rejected by `docs/ai/multimodal-vision.md` and by rule 4.

## Consequences
- **Positive:** a refusal is a first-class, demonstrable outcome at five different stages, each unit-tested and mutation-checked; no dose can come from a model; the farmer's photo is stripped, stored privately and removable; every number the UI shows about confidence was measured and says on what.
- **Trade-offs and limits (so nobody reads more into it than it holds):**
  - The measurement is on **PlantDoc**: web-scraped photos, 8 to 12 test photos per class. It is not Indian smallholder photos on low-end phones and says nothing about wheat, rice, millets, cotton or pulses, for which this system has **no** photo check yet. For the demo farm's wheat it will abstain, by design.
  - Agreement of two models is not accuracy; it is measured separately on a small subset because the vision model's free tier allows a few dozen photos a day (`evals/results/vision-pipeline-*.md`).
  - Quality-gate thresholds, the OOD threshold and the bands are fitted on PlantDoc-train and are only as good as that sample.
  - The vision model is a Preview model. Its answers can change without notice, and the closed vocabulary hides, but does not remove, that.
  - Retrieval grounding is thin: the corpus has two documents, so most diagnoses will say that no verified document backs the advice and point to the KVK (`limitations`), plus a label card where a verified row exists (tomato early and late blight today).
  - CPU cost on the free tier is not measured on the deployed host (the report gives the laptop's number).
  - The classifier is licensed CC-BY-SA-4.0 (attribution and share-alike apply to the model; AgriAI uses it unmodified, does not redistribute the weights, and credits it in the repository). A lawyer has not read this.
- **Needs a human:** Hindi names and messages read by a Hindi speaker; the disease-specific content of any label row; a wheat and rice photo set with documented classes and a field-validated model.

## Verification
Unit and integration tests (`apps/api/tests/test_vision_*.py`, `test_scans_api.py`, `test_storage_supabase.py`): sanitising (EXIF, bombs, types), the gate, the classifier wrapper and its preprocessing parity against the model's own image processor, every branch of the decision, the vision-model parsing and retry, the whole pipeline with fakes (refusals never reach the vision provider; no dose from a model; the free text guarded), the real database and the real local Storage API (row-level security for a second farmer, caps, deletion). 42 mutation checks on the vision code were applied and all killed. Evaluation: `evals/vision/` (protocol, scripts, unit tests), results in `evals/results/vision-*.md`.
